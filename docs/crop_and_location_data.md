# Crop and location data needed for field scenarios

The application can now discover supported FileX experiments in the DSSAT data folders. Each usable experiment still needs a matching model module, `.WTH` weather, `.SOL` soil profile, and cultivar table. The bundled installation includes crop-specific A-files (for example `.WHA`, `.MZA`, and `.SCA`); the project can inventory and parse their treatment tables, but crop-specific yield fields and units must be mapped before those observations are used for model training.

## Data to add for Indian state and city scenarios

For the GeoNames place-coordinate lookup, see [`data/external/geonames/README.md`](../data/external/geonames/README.md). The required `IN.zip` and `admin1CodesASCII.txt` files and normalized place CSV are already present in this workspace. The app builds a local SQLite search index from the CSV on first use. To refresh the place table from new source files, run `python scripts/import_geonames.py`.

| Purpose | Suggested source | What it can provide | Important limitation |
| --- | --- | --- | --- |
| Daily weather by location | [NASA POWER Daily API](https://power.larc.nasa.gov/docs/services/api/temporal/daily/) | Daily solar and meteorological data; the Agroclimatology community can return ICASA weather files directly. | Gridded estimates are regional, not field-station observations. The app requires complete coverage from one pre-plant day through the 365-day crop window; incomplete data fall back to installed DSSAT weather. |
| Higher-resolution India weather alternative | [IMD gridded weather overview](https://mausam.imd.gov.in/imd_latest/contents/agromet/kalp/sankalp.pdf) | IMD publishes daily gridded rainfall and maximum/minimum temperature products at India-specific resolutions. | The required solar radiation is not included in those rainfall/temperature grids; combining datasets also requires date/grid alignment and quality checks, so IMD is documented as an upgrade path rather than the active DSSAT input. |
| Soil profile matching | Georeferenced DSSAT `.SOL` profiles installed with DSSAT (including WISE profiles); for Indian field profiles, [ICAR-NBSS&LUP BHOOMI](https://bhoomigeoportal-nbsslup.in/IndianNationalSoilGrid/) | Full DSSAT layer records and profile coordinates where present. | A profile is applied only within 100 km of the selected settlement and only when SLLL, SDUL, SSAT, and SBDM are valid for every layer. A distant or incomplete profile is not presented as local. |
| Soil context / future regional estimate | [ISRIC SoilGrids](https://docs.isric.org/globaldata/soilgrids/SoilGrids_faqs_01.html) | Predicted texture, bulk density, pH, organic carbon, and water-content properties at six standard depths. | Grid predictions are not field measurements. SoilGrids' point API is currently marked as paused/beta; downloaded rasters need source, scale, coordinate, and license metadata before use. Texture or bulk density alone is not enough to synthesize a calibrated DSSAT `.SOL` file. |
| District crop outcomes | [India DES Area, Production & Yield reports](https://data.desagri.gov.in/website/crops-apy-report-web) | District, crop, season, and year level area, production, and yield. | Use for broad external comparisons. Aggregated district yields are not field-level labels for learning per-run residuals. |
| Paired residual-model training | DSSAT example `.WHX`/crop FileX inputs with matching `.WHA` observations, or local field trials with measured yield | A measured yield paired to the exact crop, treatment, soil, and weather used for a DSSAT run. | Without these matched observed outcomes, the ML model cannot learn a meaningful residual. A crop package alone may not include observations for every scenario. |

For the first data handoff, provide a DSSAT data folder or archive containing the target crop experiments plus their referenced Weather, Soil, and Genotype files. Also provide the corresponding measured `.WHA` files where available. For location-based scenarios, include the city coordinates and a documented weather period, and either DSSAT-ready soil profiles or the source soil files and metadata needed to build and calibrate them.

The current web form requires choosing a place suggestion from the selected GeoNames state. It records the settlement coordinates and selects the nearest successful installed DSSAT experiment only when that experiment is within 100 km. Otherwise it keeps the crop's available experiment. For a single-station experiment, the app requests NASA POWER daily weather from one day before planting through 364 days after planting, asks for the NASA AG community's ICASA response, validates all four DSSAT-required variables over the whole simulation window, then rewrites the weather dates into the classic DSSAT format and uses the exact weather filename referenced by the selected FileX. The pre-plant day provides the DSSAT run start before sowing. Valid responses are cached locally and reused. If the API is unavailable, the response is incomplete, or the experiment references multiple stations, installed DSSAT weather is used and the fallback reason is recorded.

For soil, the app scans installed `.SOL` files for profile coordinates and complete layer values. It uses the closest eligible profile only when it is within 100 km of the selected settlement; the selected FileX's `ID_SOIL` and staged soil directory are updated together, and the exact profile/source/distance are included in run metadata, result provenance, and CSV. If no profile passes, DSSAT retains the experiment's original soil profile and reports the nearest eligible candidate and why it was not applied. The broad soil-texture selection remains context only. The project already contains Maharashtra-named SoilGrids rasters, but they have no accompanying source/download metadata and do not include the needed full DSSAT hydraulic profile, so they are not used to create soil inputs. Do not infer hydraulic values from texture alone. To improve local coverage, provide georeferenced ICAR/NBSS&LUP or measured field `.SOL` profiles with source coordinates and provenance. GeoNames coordinates are settlement points, not exact farm coordinates; NASA POWER weather grids are not field observations.
